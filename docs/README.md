## Implementation history and research

Start with the [large-survey review guide](review-guide.md) for source entry
points and evidence. These reports describe successive stages; later reports
supersede earlier implementation details and defaults.

1. [Benchmark methodology](benchmarking.md) and [Phase 0 baseline](phase0-results.md).
2. [Phase 1: map](phase1-map.md), [Phase 2: administration](phase2-admin.md),
   and [Phase 3: preparation](phase3-preparation.md).
3. [Phase 4: storage and SQL](phase4-storage.md),
   [preparation performance](preparation-performance.md), and
   [Phase 5: fitting](phase5-fitting.md).
4. [Memory and preparation](memory-preparation.md),
   [viewport priority and GPU throughput](viewport-preparation-gpu.md), and
   [metadata preparation](metadata-preparation.md).
5. [Observation-quality research](observation-quality.md): candidate filters,
   not enabled production defaults.

Production uses immutable observation columns and SQLite metadata. DuckDB
remains a [benchmark prototype](../tools/duckbench/README.md). Historical reports
that mention active Python/NumPy parity refer to the validation at that stage;
today's Atlas parity test uses recorded fixtures entirely in Go. Compare fixture
generation still uses Python and worker parity uses Node.
